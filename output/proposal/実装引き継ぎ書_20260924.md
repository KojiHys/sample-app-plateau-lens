## 0. 作るもの（30秒で把握する用）

千代田区のPLATEAU 3D都市モデルをブラウザに表示し、建物の属性でフィルターして色分けするビューア。フィルター条件とカメラ位置を「ビュー」として保存し、自分の保存一覧から呼び戻せる。保存と一覧はCognito認証が必要。共有リンクの閲覧は認証不要。

3D描画とフィルターは**すべてクライアントサイド**。バックエンドはビューのCRUDのみ。

**実装順序は Tier 1 を完成・デプロイしてから Tier 2。** Tier 1 だけでデモが成立する。

### 0.1 命名

**全AWSリソースの接頭辞はリポジトリ名 `sample-app-plateau-lens` に統一する。** 短縮しない。アカウント内に残ったリソースを見た人が、接頭辞だけで「削除してよいサンプル」と判断できる状態を保つため（削除漏れ対策・R-07）。

## 1. 着手前の事前検証（必須・最優先）

### 検証1: Cesium ion トークンなしで3D Tilesが描画できるか

PLATEAU公式サンプルは地形を Cesium ion 経由で読むためトークンが必要になる。参加者にサードパーティ登録を求めないため、ion への通信を発生させない構成で動くことを確認する。

```js
// 確認したい構成
const viewer = new Cesium.Viewer("cesiumContainer", {
  baseLayer: Cesium.ImageryLayer.fromProviderAsync(
    Cesium.TileMapServiceImageryProvider.fromUrl(
      Cesium.buildModuleUrl("Assets/Textures/NaturalEarthII")
    )
  ),
  baseLayerPicker: false,   // ion へのアセット問い合わせを止める
  geocoder: false,          // ion のジオコーダを止める
  // terrain は指定しない（PLATEAU-Terrain は ion アセット参照のため使わない）
});

const tileset = await Cesium.Cesium3DTileset.fromUrl(
  "https://api.plateauview.mlit.go.jp/datacatalog/3dtiles/13101-bldg-lod2-latest/tileset.json"
);
viewer.scene.primitives.add(tileset);
```

**合格条件**: ブラウザのネットワークタブに `*.cesium.com` / `ion` 宛のリクエストが出ず、建物が描画される。

**失敗した場合**: オルソ画像（下記）を下敷きにする案に切り替える。それでも ion 依存が残るなら、トークンを環境変数で渡す方式に変更し、READMEに取得手順を書く。

### 検証2: 日本語・記号を含む属性名でスタイル式が動くか

属性名に `:` と全角括弧が含まれるため、`${属性名}` では解釈できない。角括弧表記でアクセスできることを確認する。

```js
tileset.style = new Cesium.Cesium3DTileStyle({
  show: "${['荒川水系神田川流域（都道府県管理区間）_L2（想定最大規模）_浸水深']} >= 0.5",
  color: "color('red')",
});
```

**合格条件**: 浸水深0.5m以上の建物のみが赤で表示される。

**失敗した場合**: スタイル式ではなく `tileset.tileVisible` イベント内で `feature.getProperty()` を使って個別に制御する方式に切り替える（実装量が増えるため、フィルター項目を絞る）。

### 検証3: JWT authorizer 経由でLambdaに `sub` が届くか

```js
// Lambda（Node.js）内
const sub = event.requestContext?.authorizer?.jwt?.claims?.sub;
```

**合格条件**: 認証付きルートで `sub` が取得でき、認証なしルートでは `authorizer` が存在しない。

## 2. データソース（実測済み・2026-09-24）

| 用途 | URL | 備考 |
|---|---|---|
| 建物 3D Tiles（千代田区 LOD2） | `https://api.plateauview.mlit.go.jp/datacatalog/3dtiles/13101-bldg-lod2-latest/tileset.json` | `-latest` は最新整備年度に自動追従。CORS `*` |
| オルソ画像 | `https://tile.plateauview.mlit.go.jp/tiles/plateau-ortho-2023/{z}/{x}/{y}.png` | `maximumLevel: 19`。CORS `*` |

**注意点**

- 複合 tileset.json は実データを `assets.cms.plateau.reearth.io` に外部参照する。CORS は同様に `*` で確認済み。ただしMLIT以外の外部依存が1つ増える（R-01）
- **本サービスは試験運用でSLA保証がない。** デモ範囲のタイルをS3にコピーし、URLを環境変数で切り替えられるようにしておく（R-01の緩和策）
- 初期カメラ位置は千代田区上空。データの範囲は実測で経度 139.730〜139.783、緯度 35.669〜35.705

## 3. フィルターUI 仕様

`tileset.json` の `properties` から実測したレンジをスライダーの初期値に使う。

### 3.1 数値スライダー

| ラベル | 属性名 | 実測レンジ | 初期値 |
|---|---|---|---|
| 高さ | `bldg:measuredHeight` | 0.8 〜 209.5（m） | 全域 |
| 地上階数 | `bldg:storeysAboveGround` | 1 〜 44（階） | 全域 |
| 屋根投影面積 | `uro:BuildingDetailAttribute_uro:buildingRoofEdgeArea` | 1.54 〜 22,322.6（m²） | 全域 |
| **浸水深（神田川 L2）** | `荒川水系神田川流域（都道府県管理区間）_L2（想定最大規模）_浸水深` | 0.1 〜 3.42（m） | 全域 |

### 3.2 分類チェックボックス

| ラベル | 属性名 |
|---|---|
| 建物用途 | `bldg:usage` |
| 用途地域 | `uro:BuildingDetailAttribute_uro:districtsAndZonesType` |

分類値の一覧は固定でハードコードせず、ロード済みフィーチャから収集して動的に組み立てる（都市を変えても壊れないようにする）。

### 3.3 着色レイヤー（ラジオボタン・凡例付き）

| 選択肢 | 属性 | 表現 |
|---|---|---|
| 用途 | `bldg:usage` | 分類ごとの離散色 |
| 高さ | `bldg:measuredHeight` | 低→高のグラデーション |
| 浸水深 | `荒川水系神田川流域（都道府県管理区間）_L2（想定最大規模）_浸水深` | 浅→深のグラデーション。値なしはグレー |
| なし | ― | 単色 |

### 3.4 デモ用プリセットボタン（1つだけ用意する）

**「垂直避難の受け入れ先候補」** を押すと下記が一括適用される。デモの山場をワンクリックで再現できるようにする。

```
浸水深（神田川 L2） >= 0.5
かつ 地上階数 >= 4
かつ 屋根投影面積 >= 1000
着色 = 浸水深
```

### 3.5 その他の利用可能属性（属性パネル表示用）

`bldg:class` / `bldg:address` / `bldg:storeysBelowGround` / `uro:BuildingIDAttribute_uro:buildingID` / `uro:BuildingDetailAttribute_uro:specifiedBuildingCoverageRate`（60〜80%）/ `uro:BuildingDetailAttribute_uro:specifiedFloorAreaRate`（300〜1300%）/ `uro:BuildingDetailAttribute_uro:fireproofStructureType` / `隅田川・新河岸川流域（都道府県管理区間）_L2（想定最大規模）_浸水深`（0.01〜4.05m）/ `高潮浸水想定_東京都高潮浸水想定区域図（令和6年12月19日）_浸水深`（0.01〜3.85m）/ `土砂災害リスク_急傾斜地の崩落_区域区分コード`（1〜2）

**注意**: `_lod` プロパティの実測レンジが 1〜2 だった。LOD2指定のtilesetにLOD1のフィーチャが混在する可能性がある。箱型の建物が混じる場合は `_lod` でのフィルターを検討する。

## 4. バックエンド仕様

### 4.1 API

HTTP API（API Gateway v2）。**ルートごとにauthorizerを設定し、認証あり／なしを混在させる。**

| メソッド | パス | 認証 | リクエスト | レスポンス |
|---|---|:---:|---|---|
| `POST` | `/views` | 必須 | `{ title, filterState, cameraState }` | `201 { viewId, shareUrl }` |
| `GET` | `/views` | **必須** | ― | `200 { items: [{ viewId, title, createdAt }] }` |
| `GET` | `/views/{viewId}` | 不要 | ― | `200 { viewId, title, filterState, cameraState, createdAt }` / `404` |
| `DELETE` | `/views/{viewId}` | 必須 | ― | `204` / `403` / `404` |

**CORS**: 許可オリジンはCloudFrontのドメインに限定する。`*` にしない。

**スロットリング**: `POST` と `DELETE` にルートレベルのスロットリングを設定する（`aws apigatewayv2 update-stage --route-settings`）。

### 4.2 認可ロジック（最重要・ここを間違えない）

```js
// GET /views
// 正: JWTクレームから取得する
const ownerSub = event.requestContext.authorizer.jwt.claims.sub;

// 誤: クライアント入力を信用する（他人の一覧が引ける = IDOR）
// const ownerSub = event.queryStringParameters.owner;   ← 絶対に書かない
```

`DELETE /views/{viewId}` は、GetItem して `ownerSub` を取得し、JWTの `sub` と一致しなければ `403` を返す。

**READMEに「なぜクライアントから所有者を受け取らないのか」を1段落で書く。** これが本サンプルの主要な教材ポイント。

### 4.3 DynamoDB

1テーブル + 1 GSI。オンデマンドキャパシティ。

| | パーティションキー | ソートキー |
|---|---|---|
| ベーステーブル | `viewId`（String, UUID v4） | ― |
| `GSI1` | `ownerSub`（String） | `createdAt`（String, ISO8601） |

GSI1 の射影は `KEYS_ONLY` ではなく `INCLUDE`（`title`）または `ALL` とし、一覧取得で追加の読み取りが発生しないようにする。

**アイテム構成**

| 属性 | 型 | 内容 |
|---|---|---|
| `viewId` | S | UUID v4。推測不可能であることが共有リンクの前提 |
| `ownerSub` | S | Cognito の `sub`。**メールアドレスは保存しない** |
| `ownerName` | S | 表示名（任意入力。個人情報を入れない注意書きをUIに出す） |
| `title` | S | ビュー名。**最大50文字でバリデーション** |
| `filterState` | M | フィルター条件（属性名→レンジ／選択値） |
| `cameraState` | M | `destination`（経度・緯度・高度）と `orientation`（heading / pitch / roll） |
| `createdAt` | S | ISO8601（JST基準ではなくUTCで保存し、表示時に変換） |

一覧は必ず GSI1 の Query で取得する。**Scan は使わない。**

### 4.4 Cognito

| 項目 | 設定 |
|---|---|
| ユーザープール | 1つ。managed login 用のドメインを割り当てる |
| 自己サインアップ | **無効**（`AdminCreateUserConfig.AllowAdminCreateUserOnly = true`） |
| アプリクライアント | SPA用のパブリッククライアント（クライアントシークレットなし） |
| 認証フロー | Authorization Code Grant + PKCE |
| コールバックURL | CloudFrontのドメイン |
| APIに渡すトークン | **IDトークン**（`aud` がアプリクライアントIDになり、`sub` も含まれるため最も単純）。JWT authorizer の `audience` にアプリクライアントIDを設定する |

**READMEに注記**: 本番でAPI認可を行う場合、AWSはリソースサーバとスコープを定義したうえでアクセストークンを使う方式を推奨している。本サンプルは簡潔さを優先してIDトークンを使っている。

### 4.5 ホスティング

S3 + CloudFront。S3は **OAC** でCloudFront経由のみに限定し、パブリックアクセスをブロックする。SPAのため404を `index.html` に返すルーティングを設定する。
